# Phase 2 – Requirement Analysis

## 1. Functional Requirements

### Request Submission

The user should be able to submit an IT procurement request through
the ServiceNow Service Catalog.

### Request Information

The request should capture required information such as:

- Requester details
- IT equipment required
- Quantity
- Business justification
- Additional information

### Approval

The submitted request should be sent to the appropriate approver.

### Automated Task Creation

After approval, procurement-related tasks should be created
automatically using Flow Designer.

### Request Tracking

The requester should be able to track the progress of the request.

### Notifications

The system should notify relevant users when the request status
changes.

## 2. Non-Functional Requirements

- User-friendly interface
- Reliable workflow execution
- Secure access
- Easy request tracking
- Reduced processing time
- Maintainable workflow

## 3. User Roles

### Requester

Submits and tracks IT procurement requests.

### Approver

Reviews and approves or rejects requests.

### Procurement/IT Team

Processes approved procurement tasks.

### Administrator

Maintains ServiceNow configuration and workflows.

## 4. Technology Requirements

- ServiceNow Platform
- Service Catalog
- Flow Designer
- Web Browser
- Internet Connection

## 5. Input

- Employee information
- Equipment details
- Quantity
- Business justification
- Additional request information

## 6. Process

Request Submission
→ Approval
→ Task Creation
→ Procurement Processing
→ Completion

## 7. Output

- Approval status
- Procurement task
- Updated request status
- Notifications
- Completed request
